# App structure: tooling and resolution evidence

This note records the checks behind [ADR 0037](../adr/0037-app-structure.md), gathered in October 2026. Each claim was either tested on a scratch project or read from the tool's own documentation or issue tracker. The tested versions were TypeScript 6.0.3, Vite 8.3.2, Vitest 5.0.3 and Node 24.16.

## Subpath imports

| Claim                                                                                  | Result                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vite uses only the first entry of a `package.json` `imports` array                     | **Confirmed.** [vitejs/vite#16153](https://github.com/vitejs/vite/issues/16153) was closed as not planned. On Vite 8.3.2, `["./src/*.ts", "./src/*.tsx"]` fails the build for a `.tsx` target, while TypeScript resolves both.                                                                                                                        |
| An extensionless `"#*": "./src/*"` target works with TypeScript's `bundler` resolution | **No.** TypeScript 6.0.3 resolved neither `#utils/formatDate` nor `#utils/formatDate/formatDate` against it. Apps using that map only work because Vite resolves the path itself. [TypeScript#60423](https://github.com/microsoft/TypeScript/issues/60423) describes related auto-import trouble, but is open and unconfirmed, so it isn't relied on. |
| The longest matching `imports` key wins, so `#testing/*` beats `#*`                    | **Confirmed** in Node (its `PATTERN_KEY_COMPARE` ordering), Vite, Vitest and TypeScript, with a decoy `src/testing/` folder present.                                                                                                                                                                                                                  |
| `"#*": "./src/*/index.ts"` works across the toolchain                                  | **In TypeScript, Vite and Vitest, yes.** Node resolves the specifier, but can't execute the extensionless relative re-exports (`export { X } from './X'`) inside `index.ts`, so the structure is for Vite-bundled apps.                                                                                                                               |
| Narrow named re-exports tree-shake                                                     | Expected from how Rollup and esbuild treat named re-exports, but not measured. The measurable cost is the extra modules Vite's dev server loads, about one per module.                                                                                                                                                                                |

## Lint tooling

The question was whether existing plugins can enforce the structure without custom ESLint rules. Each candidate was tried on a fixture with `#*` imports, two features, nested modules, shared code, an `app/` root and tool-convention files.

| Tool (version, date)                                  | What it covers                                                                                                              | Notes                                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `eslint-plugin-boundaries` 7.2.0 (2026-08-09)         | Owner privacy, feature public surfaces, shared code not importing features, direction rules generated from a declared graph | Ownership maps onto its `internal`/`child`/`sibling`/`uncle` relationship selectors. Shared top-level modules need an extra `parent: null` policy. Alternation globs like `(a\|b)/*` silently fail to match, but brace globs like `{a,b}/*` work. Version 7 folded the older rules into `boundaries/dependencies`. |
| `eslint-plugin-project-structure` 3.14.5 (2026-09-30) | Folder shape, kind names, module folders, main-file names, ignore patterns                                                  | `enforceExistence` takes literal paths, so there's one entry per main-file extension. It doesn't see empty folders. It writes a cache file that should be gitignored. It has a single maintainer.                                                                                                                  |
| Core ESLint                                           | `index.ts` content (`no-restricted-syntax`) and `../` imports (`no-restricted-imports`)                                     | Caught `export *`, local declarations, and re-exports from subfolders or parent folders.                                                                                                                                                                                                                           |
| `eslint-plugin-import-x` 4.17.1                       | `no-cycle` is file-level                                                                                                    | Two features that depend on each other through different files have no file cycle, so this misses them.                                                                                                                                                                                                            |
| dependency-cruiser 18.5.0                             | Feature cycles, via `--collapse` plus a short script                                                                        | Folder-scoped `circular` rules missed the feature cycle, because folder edges point at leaf folders. Running `depcruise --collapse '^src/features/[^/]+' -T json` through a script did catch it. It covered 1,959 modules in 1.7 s, but only in CI.                                                                |
| Sheriff 0.20.0                                        | Barrel-based encapsulation, tags                                                                                            | Pre-1.0. Its circular-dependency check is an empty stub in this version.                                                                                                                                                                                                                                           |
| Steiger 0.7.0                                         | Feature-Sliced Design only                                                                                                  | Not extendable with new rules.                                                                                                                                                                                                                                                                                     |
| Nx `enforce-module-boundaries` 23.3.0                 | Project-level cycles                                                                                                        | Needs every feature to be an Nx project.                                                                                                                                                                                                                                                                           |

No tool detected a cycle between features when no file-level cycle existed, apart from Nx and the dependency-cruiser script. A feature graph declared in the ESLint config, with the generated `boundaries` policies and a cycle check that runs when the config loads, gave the same protection in the editor. A declared cycle failed with `feature cycle: alpha -> beta -> alpha`.

## Test-support conventions

- The only test folder names tools give meaning to are Vitest's and Jest's `__mocks__` and `__snapshots__`, and Jest's `__tests__` ([Vitest mocking](https://vitest.dev/guide/mocking/modules), [Jest manual mocks](https://jestjs.io/docs/manual-mocks)).
- `__fixtures__` appears in third-party packages and blog posts, not in Jest's documentation.
- MSW recommends splitting handlers by domain and combining them in one list ([MSW, structuring handlers](https://mswjs.io/docs/best-practices/structuring-handlers)).
- bulletproof-react and Epic Stack keep all test support in one root folder. Feature-Sliced Design's docs don't cover tests.
- Placing fixtures and handlers per feature is therefore Kiln's own convention.

## Type naming

- The TypeScript team's coding guidelines ("Do not use `I` as a prefix for interface names") and the [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html) both advise against `I` and `T` prefixes.
- Neither distinguishes `interface` from `type` by name.
- Codebases resolve a page and a type with the same name by suffixing one of them:
  - Supabase Studio and Plane use `UsersPage`;
  - React Router's tutorial uses `ContactRecord`.
- Kiln leaves the choice to the project.
