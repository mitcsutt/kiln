A `Button` starts something: saving, publishing, opening a dialog. If it takes the reader somewhere instead, it's a link, and `asChild` lets a link look like a button when it's the primary way forward.

<Example of="Button" name="Hierarchy" />

## Hierarchy

One solid button per view: it _is_ the primary action. Secondary actions are `outline`, and the quiet ones (cancel, dismiss) are `ghost`. Labels are specific verbs: "Publish timetable", not "Submit"; "Export CSV", not "Learn more".

## Tones

`accent` (the default) is the theme's action colour. `neutral` is ink, for actions that shouldn't compete. `critical` is for destructive actions only, and works best behind a confirmation.

<Example of="Button" name="Tones" />

## Sizes

`sm`, `md` (the default) and `lg` share the control heights with inputs and selects, so a button lines up with a field of the same size.

<Example of="Button" name="Sizes" />

## Icons and links

`leadingIcon` and `trailingIcon` take any icon. Use a trailing icon only when it adds meaning, like an external link, never a decorative arrow. With `asChild`, the button renders its child (an `<a>`, or your router's link) and merges its styles onto it.

<Example of="Button" name="IconsAndLinks" />

```tsx
import NextLink from 'next/link'

;<Button asChild>
  <NextLink href="/routes/new">Plan a route</NextLink>
</Button>
```

## Loading and disabled

`loading` shows a spinner, sets `aria-busy` and ignores presses while keeping the button's width, so the layout doesn't jump. Press the first button to see it.

<Example of="Button" name="States" />

Avoid `disabled` on a form's submit button: a disabled button can't be focused, so keyboard and screen reader users never learn why they can't continue. kiln-forms' `SubmitButton` uses `aria-disabled` with a reason instead.
